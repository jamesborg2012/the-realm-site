# Changes

Backlog of client-requested changes for The Realm Malta.

## Workflow

- One item = one session = direct commits to master (no PR / branch).
- At the start of each session, Claude reads this file and **asks for a brief** on the chosen item before implementing — items below are names only.
- Items move: `Backlog` → `In Progress` (with brief) → `Done` (with commit SHA + 1-line outcome) or `Dropped` (with reason).
- Cross-cutting decisions that should bind future work go to Claude memory, not here.

- [x] **26. Cost Price Backdated Improvement** _(commit pending)_ — cost prices can now be **backdated** so past sales report true profit. Root cause: the system stored a single `uploaded_at` per row that silently meant *both* "recorded on" and "valid from", and profit analytics binned each sale to the latest row with `uploaded_at <= order_date` — so a price entered today could never fix last month's sales, and "current price" was defined as `MAX(id)`. **Fix:** added a distinct **`effective_date DATE`** column ("valid from") separate from `uploaded_at` (audit only); DB version bumped `1.1`→`1.2` (dbDelta adds the column + index; install backfills `effective_date = DATE(uploaded_at)` for legacy rows). **"Current" redefined** from `MAX(id)` to *greatest `effective_date` on/before today, id as tie-break* — a backdated row has a higher id but earlier effective date, so `MAX(id)` would wrongly treat it as current; every current-price query (`get_current_price`, `get_all_current_prices`, `get_current_prices_by_product_ids`, `get_current_price_with_product`) rewritten as a greatest-effective-date lookup / anti-join (window-function-free, MariaDB/5.7-safe). **Profit Analytics** now bins by `effective_date` (history fetched `ORDER BY effective_date ASC, id ASC`; period boundaries computed from it). **UI:** each product's history `<details>` panel became a managed, dated list — every record shown by effective date with the current one **badged**, each row **editable/deletable**, plus an **"Add a cost price for a past date"** form (price + valid-from date). New AJAX (nonce `trm_cost_price_inline`, cap `manage_woocommerce`): `trm_cost_price_add_dated` → `insert_dated_price()` (`source='manual'`, append-only), `trm_cost_price_update_row` → `update_row()` (edits price/effective date, leaves `uploaded_at`), `trm_cost_price_delete_row` → `delete_row()`; each returns the recomputed current price so the main cell + badge refresh live. Future dates rejected server-side. Inline "today" edit unchanged in UX (now writes `effective_date = today`; collapse rule tightened to today-effective inline rows only, so a backdated `manual` row is never overwritten). CSV uploads stamp `effective_date = today`.
